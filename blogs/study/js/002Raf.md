## requestAnimationFrame（RAF）


`requestAnimationFrame`（简称 RAF）是 HTML5 提供的浏览器动画 API。

> 作用：在浏览器下一次重绘之前执行指定回调

语法：

```js
const rafId = requestAnimationFrame(callback)
```

返回值：当前动画任务 ID,可用于取消动画：

```js
cancelAnimationFrame(rafId)
```


#### 为什么需要 RAF

传统动画通常：
+ 定时器不精确
+ 浏览器存在最小时间间隔限制(浏览器对 setInterval 有最小间隔限制（通常为 4ms 或 10ms），且后台标签页会进一步降频。)
+ 页面卡顿时会丢帧
+ 后台页面仍然执行

因此动画可能不流畅。

> 当主线程被长时间任务阻塞时，setInterval 的回调可能被积压，连续执行导致跳帧；而 RAF 的回调会与渲染同步，如果当前帧来不及执行则会跳过，从而保持与帧率的协调（即“丢帧但不积压”）。补充这一点会更深入。


### RAF 的工作原理

浏览器渲染流程：

```text
JavaScript
↓
Style
↓
Layout
↓
Paint
↓
Composite
↓
显示到屏幕
```

RAF 的回调会在：浏览器下一次重绘前执行。因此能够和浏览器刷新频率同步。

常见刷新率：

```text
60Hz
120Hz
144Hz
```

RAF 会自动适配。


#### RAF 的优势

1. 自动匹配刷新频率

无需手动计算：浏览器自动调度。

```js
setTimeout(fn,16)
```

2. 更流畅

浏览器会将同一帧中的 DOM 操作合并。减少重排（Reflow）重绘（Repaint）次数。

3. 页面隐藏自动暂停


- 切换浏览器标签页
- 最小化窗口
- 隐藏 iframe

RAF 会暂停。

而：

```js
setInterval()
```

仍可能继续执行。

因此：

```text
CPU 消耗更低
内存占用更少
```


#### RAF 实现动画和 停止 RAF

```js
let rafId

function animate() {
  left += 1
  if (left >= 100) {
    cancelAnimationFrame(rafId)
    return
  }
  rafId = requestAnimationFrame(animate)
}

rafId = requestAnimationFrame(animate)
```


#### RAF 如何控制动画速度

这是面试高频问题。

错误写法：

```js
left += 1
```

问题：

```text
60Hz 显示器每秒执行 60 次
120Hz 显示器每秒执行 120 次
```

动画速度会翻倍。


正确做法：利用 RAF 提供的时间戳参数。

```js
requestAnimationFrame(timestamp => {})
```

计算两帧之间时间差：

```js
deltaTime = currentTime - lastTime
```


示例：

```js
const speed = 100

let left = 0
let lastTime = 0

function animate(time) {
  if (!lastTime) {
    lastTime = time
  }
  const deltaTime = time - lastTime
  left += speed * deltaTime / 1000
  box.style.left = `${left}px`
  lastTime = time
  requestAnimationFrame(
    animate
  )
}

requestAnimationFrame(
  animate
)
```

表示：

```text
每秒移动 100px
```

无论：

```text
60Hz
120Hz
144Hz
```

速度都一致。
